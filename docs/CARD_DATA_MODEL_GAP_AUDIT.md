# 球星卡数据模型缺口审计（2026-09-10）

## 现有模型可以直接复用的部分

`card_variants` 已保存品牌、系列、发行年、球员、印刷球队、卡号、RC、平行、限编、签名、物料和 `identity_key`；`graded_cards` 保存评级公司、等级和证书；`card_images` 保存正反面 URL、来源与版权状态；`sales` 与 `listings` 分离并保存原币种、换算、来源 URL、授权状态和原始 JSON。

## P0 缺口

- 需要统一 canonical identity 规则：品牌别名、系列别名、卡号格式、平行/颜色标准化和评级公司代码必须由一个服务生成，不能由页面自行拼接。
- 需要在 `sales` 上补充“最终成交/拍卖成交/社区提交/挂牌误判”的事件类型和原始抓取快照校验，否则只能称为来源记录，不能称为真实成交。
- 需要给 `card_images` 增加可执行的审核状态流转（待审、已核对、拒绝、撤回）和版权到期字段；当前 `rights_status` 只够表达结果，不够表达审批过程。
- 需要以 `source_sale_id + marketplace_id` 做幂等导入，并将重复、异常、低置信记录自动写入 `review_queue`。
- 需要将 all-in 成本、运费、税费、平台费与净到手价固定为可复算字段，避免把挂牌价当成收益。

## P1 缺口

- `price_snapshots` 应区分窗口（24H/7D/30D）、样本策略和计算版本，支持重算与回溯。
- 增加来源健康、同步游标、速率限制、失败重试和数据保留期限，供后台查看。
- 为球员卡匹配保留候选集合、匹配证据与人工确认人，处理 Jr./III、重音符号、连字符和昵称。
- 将首页市场指标改为服务端查询结果；无授权来源时继续显示演示快照和“样本不足”，不降级为猜测。

## 验收口径

同一张卡在不同平台出现时必须归并到同一 `identity_key`；挂牌不能进入成交统计；异常和重复样本保留原始记录但排除出参考价；任何卡图都必须能追溯来源、授权状态和最后核验时间。
